# T-055 (R-010): Phone/pitch-side goal eval set, `goal_coverage`, and eval with `top=None`

> For agentic workers: follow the steps in order (TDD). Each step is one action with a result you can check.

**Goal:** Measure first. The PO reports that goal clips from their own pitch-side phone videos are wrong. The eval set today is broadcast-style only (scoreboard, replays), so it cannot show this. This task adds a synthetic phone-style eval set and a `goal_coverage` score: does a predicted `goal` clip contain the whole goal, build-up included? It also makes `sportscut eval` score the same candidates that `sportscut cut` uses (`find_highlights(top=None)`). Detection code does not change; fixing detection is a later task, guided by this number.

**Architecture:** There is a new fixture builder, `tests/fixtures/eval_phone/build.py`. It loads `tests/fixtures/eval/build.py` with importlib and reuses its constants and noise helpers. It writes `<case>/labels.json` (committed) and `<case>/video.mp4` (git-ignored). `sportscut/evaluate.py` gains a pure helper `covered_goals` and one top-level report key, and it calls `detect.find_highlights(video, top=None)`.

**Tech stack:** Python 3.11, numpy, ffmpeg (already required), pytest.

## Context (read before coding)
- `sportscut/evaluate.py::evaluate_dir` scores `audio_cues.tag_saves(video, incidents.tag_incidents(video, scoreboard.tag_goals(video, detect.find_highlights(video))))`. It calls `find_highlights` with its default `top=10`. `pipeline.run` calls `find_highlights(video, top=None, min_len, max_len)` and only caps the result later in `ranking.select_segments`. So the eval can score fewer candidates than `cut` exports from. The T-010/T-013/T-015 decisions fixed the default-options call. This task changes them.
- `scoreboard.tag_goals`: `find_box` takes the largest static, high-edge component in the top 30 rows as the 'scoreboard'. `score_changes` turns lasting changes inside it into 'goals'. On phone footage a fence or roofline in that band looks like a board, and a camera pan looks like a score change. The new fixture models exactly this. The task does not fix it.
- Broadcast eval set: 4 x 180 s matches, at most 7 predictions per match (README 'Kết quả sau T-015'). So `top=None` should not change any broadcast number.
- `tests/fixtures/eval/build.py` is frozen by ungated scope tests (test_t013_acceptance, test_t014_acceptance, test_t015_acceptance FORBIDDEN sets). It must NOT be edited. Its ffmpeg encode step (`_encode_match`) depends on its own `MATCHES`, so the phone builder has its own small encode function. It still imports and reuses `W, H, FPS, AUDIO_RATE, _band_noise, _ramp`.

**Labels.** For each goal `(t0, d)` the label is `{"start": t0-10, "end": t0+6, "type": "goal"}`. For each chance it is `{"start": t0-4, "end": t0+4, "type": "chance"}`. The gust and the whistles get no label. The values are:
- pitch_a: [46,54] chance, [110,126] goal, [266,274] chance, [385,401] goal, [516,524] chance.
- pitch_b: [86,94] chance, [190,206] goal, [326,334] chance, [440,456] goal, [536,544] chance.

The file text is `json.dumps(case_labels(name), indent=1) + "\n"`, the same format as the broadcast set.

**Picture (no scoreboard, no digits drawn anywhere):**
- rows 0-7: sky (170,190,210).
- rows 8-9: roofline (30,30,30), full width.
- rows 10-21: fence background (60,60,60) with white posts (230,230,230) in every column x where `(x - pan_offset(name, t)) % 8 in (0, 1)`.
- rows 22-89: grass (40,140,60).
- A 5x5 white disc ball (same disc mask as the broadcast builder) is centred at `bx = round(80 + 60*sin(0.37*t))`, `by = round(60 + 20*sin(0.23*t + 1))`.

The band is static between pans and jumps by exactly 3 px at each pan. W=160 is a multiple of 8, so `np.roll(band, 3, axis=1)` gives the band after a pan.

**Audio.** `rng = np.random.default_rng(seed)`. Draw the layers in this order:
- `ambient = _band_noise(rng, n, 100, 4000)`
- `cheer = _band_noise(rng, n, 300, 3000)`
- `gust = _band_noise(rng, n, 30, 300)`

The mix is `AMBIENT_RMS*ambient + cheer_env*cheer + gust_env*gust + whistles`:
- `cheer_env` is `EVENT_RMS` over every goal span `[t0, t0+d)` and every chance span, with a 0.3 s `_ramp` from 0 at the start and down to 0 at the end. It is 0 elsewhere.
- `gust_env` follows the same rule over the gust span.
- Each whistle is a 1.0 s sine at 3000 Hz, amplitude 0.1, with 20 ms linear fades, starting at `t0 + 40` for every goal.

Clip the mix to [-1, 1] and return float32.

**Encode.** `_encode(name, output)` copies the broadcast ffmpeg argument list exactly (rawvideo rgb24 160x90 at 10 fps from a pipe, plus a 16-bit mono WAV, `-c:v mpeg4 -q:v 2 -pix_fmt yuv420p -c:a aac -b:a 64k -ar 16000 -ac 1 -t 600`). It writes to `.video.tmp.mp4` first and then calls `os.replace`, and deletes the temp file on any error. `build_all` has the same rules as the broadcast builder: rewrite labels.json only when its text changed, and encode only when the video is missing, the labels changed, or `force` is set.

### sportscut/evaluate.py
```python
def covered_goals(segments: Sequence[Segment], labels: Sequence[Label]) -> int:
    """Number of labels with type 'goal' fully inside at least one segment whose event is 'goal'
    (segment.start <= label.start and label.end <= segment.end, inclusive, no epsilon)."""
```
In `evaluate_dir`:
- Call `detect.find_highlights(video, top=None)`: video positional, `top=None` keyword, no other arguments. The rest of the chain is unchanged and is still called through module attributes.
- Pool `goal_labels` (count of labels with `type == "goal"`) and `goals_covered` (the sum of `covered_goals`) over all matches.
- Return `{**summarize(totals), "goal_coverage": round(goals_covered / goal_labels, 4) if goal_labels else None, "per_match": per_match}`, so the key order ends with `..., "precision_at_5", "goal_coverage", "per_match"`.
- `summarize`, `score_case` and the per_match entry keys do not change.
- The CLI does not change: it already prints the dict.

## Assumptions
- The cue model (cheer, whistle, fence, pans) stands in for real phone footage until the PO adds labelled matches in `data/eval/`. No real media is committed.
- 'chance' labels map to event 'other' through the existing `to_event` and count only in f1, precision and recall. `goal_coverage` uses goal labels only.
- `goal_coverage` is top-level only. Per-match entries keep their exact key list, which existing tests pin.
- A segment may cover several goal labels. Coverage is not one-to-one matching.
- The phone baseline values are recorded, not gated. The expected low numbers are what the next fix task will improve.
- The README phone JSON must equal the live eval output exactly. Fixture inputs are seeded and deterministic, which is the same precedent as the pinned broadcast values.
