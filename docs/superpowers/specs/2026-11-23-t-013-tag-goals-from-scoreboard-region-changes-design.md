# T-013: Tag goals from scoreboard-region changes plus sustained crowd roar

Request R-003. Plan: `docs/superpowers/plans/2026-11-23-t-013-tag-goals-from-scoreboard-region-changes.md`.

## Product Owner request

Highlight theo sự kiện: gắn nhãn bàn thắng, cứu thua, thẻ đỏ, pha tranh cãi. Người dùng lọc "chỉ bàn thắng" hoặc "top 5 pha hay".

## Goal

Add `sportscut/events/scoreboard.py`. It samples frames at 1 fps, downscaled (ffmpeg `fps=1,scale=160:-1`, gray), finds the most static high-edge box in the top band, and flags times where that box changes and then stays stable again. That is a score change, found without OCR. A goal = a scoreboard change within about 60 s after an audio peak with a sustained roar (≥ 6 s above baseline). The segment is anchored on the audio peak, and a scoreboard change with no matching audio candidate adds its own candidate 30-60 s earlier. Report `goal` precision/recall before and after in the PR. Merge only if goal recall ≥ 0.95 on the synthetic set, overall F1 does not drop, and a 90-minute pass stays inside the 10-minute budget (frame sampling at 1 fps is about 5,400 tiny frames). Assumption: broadcasts with no visible scoreboard fall back to the roar-only rule with lower confidence.

- Classifying save, red_card or controversy (separate R-003 tasks)
- Handling running match clocks, sponsor animations or multiple scoreboards in real broadcasts beyond the static-pixel mask
- Restricting the roar to the crowd frequency band (e.g. to tell booing from cheering in fallback mode)
- Sharing one audio decode between find_highlights and tag_goals (caching)
- Changing `sportscut detect` CLI output (it stays audio-only and untagged)
- Retuning ranking weights or the eval matching rules
- Changing the synthetic eval set or its labels
- A web/UI display of event confidence

## Decisions

- T-013 (R-003): Goal tagging lives in `sportscut/events/scoreboard.py`. Its I/O entry point is `tag_goals(video, segments, min_len=10, max_len=30) -> list[Segment]`, and pure helpers `find_box`, `score_changes`, `roar` and `match_goals` hold all the logic. `sportscut.media` stays the only module that runs ffmpeg: it gains `sample_top_band(path)`, which returns (n,30,160) uint8 from one call with `-an -vf fps=1,scale=160:90,format=gray,crop=160:30:0:0 -f rawvideo -pix_fmt gray`.
- T-013 (R-003): Frames are scaled to a fixed 160x90 (not 160:-1), so each cropped raw frame is exactly 4800 bytes and no extra probe is needed. The stretch on non-16:9 sources is harmless for change detection. Sample i is time i s.
- T-013 (R-003): Scoreboard box: the pixels that are static (median |frame diff| <= 2) and high-edge (edge >= 40 on the temporal-median image) are dilated by 2 px and 8-connected. The component with the most such pixels wins (at least 12 pixels, else there is no scoreboard), and its bounding box is the box. A change is a run of samples where >= 3% of box pixels flip by >= 40 gray levels, followed by 3 stable samples, with the final state differing from the state before the run. It is timed at the first sample of the run.
- T-013 (R-003): Sustained roar is the maximal run of seconds at or above 6.0 dB residual (per-second dB minus the T-002 121 s rolling median) that contains the segment's peak second (first argmax inside the segment). It must last at least 6 s. `detect.loudness_residual` and `detect.place_window` are extracted from find_highlights with identical behaviour, and the scoreboard module reuses them.
- T-013 (R-003): Matching: a change c matches a segment with peak p when p-10 <= c <= p+60. Pairs are assigned one-to-one, greedily by (|c-p|, c, index). Only segments with event 'other' are relabelled. A match gives event 'goal', confidence 0.9, and the reason suffix '; scoreboard change at <c:.0f>s'. Start, end and score are unchanged, so the segment stays anchored on the audio peak.
- T-013 (R-003): An unmatched scoreboard change adds `Segment(place_window(c-45, L, duration, L/2), score=3.0, reason='scoreboard change at <c>s', event='goal', event_confidence=0.6)` with L = clamp(30, min_len, max_len), which is [c-60, c-30] by default. It is dropped if it overlaps any kept segment (touching allowed), so returned segments never overlap.
- T-013 (R-003): If no scoreboard box is found, every qualifying 'other' segment becomes 'goal' with confidence 0.4 and the reason suffix '; sustained roar <run>s'. Nothing is added. Confidence levels are 0.9 (roar + scoreboard), 0.6 (scoreboard only) and 0.4 (roar only).
- T-013 (R-003): `pipeline.run` calls `tag_goals` between `find_highlights(top=None)` and `select_segments`, filling the T-012 classifier slot. `evaluate_dir` calls `scoreboard.tag_goals(video, detect.find_highlights(video))` through the module attribute, so `sportscut eval` measures detector plus classifiers. This updates the T-010 decision that the eval calls only find_highlights. `sportscut detect` stays audio-only. (updated by T-014: tag_saves runs right after tag_goals in pipeline.run and evaluate_dir; stubbed eval tests also stub audio_cues.tag_saves) (updated by T-015: tag_incidents runs between tag_goals and tag_saves in pipeline.run and evaluate_dir; stubbed eval/pipeline tests also stub tag_incidents as pass-through)
- T-013 (R-003): Eval tests that feed fake or empty video files through a stubbed `detect.find_highlights` must also stub `scoreboard.tag_goals` as identity. Adding that stub follows the intended spec change and does not weaken those tests. T-023's `test_ac16` scope check drops 'sportscut/evaluate.py', because a per-task scope rule cannot freeze a file for later tasks (same reasoning as the T-011 round-1 Tech Lead decision). It keeps export.py, pyproject.toml and tests/conftest.py. (updated by T-014: tag_saves runs right after tag_goals in pipeline.run and evaluate_dir; stubbed eval tests also stub audio_cues.tag_saves) (updated by T-015: tag_incidents runs between tag_goals and tag_saves in pipeline.run and evaluate_dir; stubbed eval/pipeline tests also stub tag_incidents as pass-through)
- T-013 (R-003): Merge gate: on the synthetic set, goal recall >= 0.95, goal precision >= 0.8, overall F1 >= 0.8421 (T-011 baseline), and an opt-in 90-minute check (`SPORTSCUT_PERF=1`, 5400 s 640x360 25 fps video) finishing detection + tag_goals in < 600 s. Results go in the README under 'Kết quả sau T-013' and are checked only as invariants, never against a live run.
