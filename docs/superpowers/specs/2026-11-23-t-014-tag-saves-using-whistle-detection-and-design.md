# T-014: Tag saves using whistle detection and roar shape

Request R-003. Plan: `docs/superpowers/plans/2026-11-23-t-014-tag-saves-using-whistle-detection-and.md`.

## Product Owner request

Highlight theo sự kiện: gắn nhãn bàn thắng, cứu thua, thẻ đỏ, pha tranh cãi. Người dùng lọc "chỉ bàn thắng" hoặc "top 5 pha hay".

## Goal

Add `sportscut/events/audio_cues.py` with a whistle detector: narrow-band energy at 2-4 kHz against broadband, at least 0.3 s long. It also adds roar-shape features per candidate: rise time, duration above baseline, decay. Save = a sharp, short roar (< 4 s above baseline) with no scoreboard change and no whistle within the next 5 s; anything that is not a goal and does not match stays `other`. Also export the whistle/stoppage features for task 6 to reuse. Report per-event numbers before and after in the PR. Merge only if save recall improves, goal metrics and overall F1 do not drop, and processing time stays within budget. Assumption: thresholds are tuned on the synthetic set only, and the README notes that real-match tuning needs the PO's labelled `data/eval/`.

## Decisions

- T-014 (R-003): Save tagging lives in `sportscut/events/audio_cues.py`. Its I/O entry point is `tag_saves(video, segments) -> list[Segment]`. Pure helpers `window_levels`, `band_share`, `find_whistles`, `stoppage_after`, `roar_shape` (returns NamedTuple `RoarShape(peak, start, end, duration, rise, decay)`) and `match_saves` hold all the logic. ffmpeg is reached only through `sportscut.media.extract_audio` and `scoreboard.board_changes`.
- T-014 (R-003): Audio features use fixed 0.1 s windows (1600 samples at 16 kHz). Window i covers [i/10, (i+1)/10) s. A baseline is the median over windows [i-600, i+600] (about the T-002 121 s window). Band energies use a Hann window, and the FFT runs in chunks of 600 windows to bound memory on 90-minute audio.
- T-014 (R-003): A whistle is a maximal run of at least 3 windows (0.3 s) where the 2000-4000 Hz band holds >= 0.5 of the Hann-windowed power. It is reported as (i/10, j/10). Zero-power windows have share 0.0. White noise (share about 0.25) is never a whistle.
- T-014 (R-003): Stoppage feature for T-015: `stoppage_after(samples, at)` counts consecutive 0.1 s windows from round(at*10) whose 300-2000 Hz play-band power is at least 6 dB below that band's median over ±60 s. Booing (below 220 Hz) does not count as play sound. It returns seconds.
- T-014 (R-003): Roar shape. peak = first argmax window inside the segment. start/end/duration = the maximal run >= baseline+6 dB containing the peak. rise = from the first window >= baseline+3 dB within the 5 s before the peak (not necessarily contiguous, matching T-011's rise definition) to the first window within 2 dB of the peak. decay = windows after the last near-peak window that are still inside the run. A peak below +6 dB gives an all-zero shape at the peak time.
- T-014 (R-003): Save rule. Only segments still `other` after tag_goals qualify. Conditions: 0 < duration < 4.0 s, rise <= 0.5 s, no whistle overlapping [roar start, roar end + 5 s), and no scoreboard change in [peak-10 s, peak+30 s] (both bounds inclusive). A save gets event 'save', confidence 0.6 and the reason suffix '; sharp roar <duration:.1f>s'. Start, end and score are unchanged, nothing is added or removed, and order is kept.
- T-014 (R-003): Without a visible scoreboard (`board_changes` returns None), nothing is tagged save, and tag_saves returns before decoding audio. 'No scoreboard change' cannot be checked then, so the conservative choice also keeps no-scoreboard videos (e.g. the conftest burst_video) all `other`.
- T-014 (R-003): The save scoreboard window is [peak-10, peak+30], narrower than T-013's goal window (+60 s). The synthetic set has saves 44-56 s before the next goal's change, and 30 s still covers the usual broadcast score-graphic delay.
- T-014 (R-003): `scoreboard.board_changes(video) -> list[float] | None` is extracted from tag_goals with identical behaviour. tag_saves calls it through the module attribute, so tests can stub it.
- T-014 (R-003): Classifier chain: `pipeline.run` calls `tag_saves(video, candidates)` right after `tag_goals` and before `select_segments`, inside the same MediaError/ValueError -> PipelineError block. `evaluate_dir` scores `audio_cues.tag_saves(video, scoreboard.tag_goals(video, detect.find_highlights(video)))`. This updates the T-013 decisions on the pipeline/eval call chain. T-015 adds its classifiers to the same chain and owns the precedence goal > red_card > controversy > save. (updated by T-015: tag_incidents runs between tag_goals and tag_saves in pipeline.run and evaluate_dir; stubbed eval/pipeline tests also stub tag_incidents as pass-through)
- T-014 (R-003): Eval tests that feed fake videos or label-derived segments through stubbed detect/tag_goals must also stub `audio_cues.tag_saves` as identity. Adding that one line follows the intended spec change and does not weaken those tests (same reasoning as the T-013 tag_goals stubs).
- T-014 (R-003): Merge gate on the synthetic set: save recall >= 0.8 and save precision >= 0.8 (from recall 0.0). goal precision/recall/f1 stay 1.0. f1 0.8421, precision 0.7273, recall 1.0 and precision_at_5 0.8889 stay identical, since only labels change. The opt-in 90-minute check (SPORTSCUT_PERF=1) runs detection + tag_goals + tag_saves with the audio path forced, in < 600 s. Results go in the README under 'Kết quả sau T-014' and are checked only as invariants.
- T-014 (R-003): Thresholds are tuned on the synthetic set only. The README says real-match tuning needs the PO's labelled `data/eval/`.
