# T-020: Detect the ball and let it drive the crop, with the player cluster as fallback

Request R-004. Plan: `docs/superpowers/plans/2026-11-23-t-020-detect-the-ball-and-let-it.md`.

## Product Owner request

Tự xuất video dọc 9:16 cho TikTok/Reels: tự bám theo bóng và cầu thủ để crop, có phụ đề và tỉ số.

## Goal

Add ball detection to the reframe module. On each sampled frame, look inside the field mask for small, bright, near-circular blobs of a plausible size (numpy grid scoring, no OpenCV). Keep the candidate closest to the previous ball position with a simple constant-velocity gate, and treat the ball as lost after N missed samples. Then the camera target is the ball when confident and the player mass when not, blended so the switch causes no jump, and the task 3 smoother is reused. Report `eval-crop` before and after. The target is ball_in_crop >= 0.95 on the synthetic set (including the occlusion and white-distractor clips) with no jitter regression and no drop in players_in_crop. Assumption: if PO-labelled real clips exist in `data/eval_crop/`, report their numbers in the PR too. A YOLO `[vision]` backend is proposed as a separate request only if real-clip ball_in_crop stays below about 0.8.

## Decisions

- T-020 (R-004): The ball is detected by numpy grid scoring on the existing 5 Hz, 320-px-wide analysis frames, with no second decode. A pixel is bright when min(R,G,B) >= BALL_LEVEL and it lies inside the T-045 field mask. A candidate is an odd s x s box (s in (3, 5)) with fill >= BALL_FILL and zero bright pixels in the 2-px ring around it, found with an integral image. Its position is the bright-pixel centroid + 0.5, its score is the fill, and greedy suppression uses a 3 px radius. Lines, white kits and large blobs are rejected by the empty-ring rule.
- T-020 (R-004): `field_mask` is extracted from player_mask without changing behaviour, and both player_mask and ball_candidates use it.
- T-020 (R-004): The tracker is a constant-velocity gate. Acquisition takes the highest score. While tracking, it picks the nearest candidate within BALL_GATE*analysis width of pos + vel*(misses+1), and velocity is updated over the gap. While coasting it holds the last hit. After BALL_LOST consecutive misses the ball is lost (None), and the next sample reacquires globally.
- T-020 (R-004): Ball confidence is a weight w that ramps by BLEND_STEP per sample: up while the tracker outputs a position, including while coasting, and down once the ball is lost. It starts at 1 if the ball is found at sample 0. The camera target cross-fades between the ball-mode target and the T-045 player target with w, so switching causes no jump.
- T-020 (R-004): The ball-mode target is not the bare ball. It is the heaviest crop-wide player window whose centre lies within ±(0.5 - BALL_EDGE)*crop width of the ball, clamped to that range, or the ball itself when there is no player mass. This keeps the ball in the crop without lowering players_in_crop, which a pure ball-centred camera would do (estimated about 0.54 vs 0.5988 on the synthetic set).
- T-020 (R-004): The T-045 smoother is reused. smooth_path accepts per-sample dead_zone, ease and max_pan sequences, and scalars behave exactly as before. plan_crop interpolates them between the unchanged player constants (0.06/0.2/0.1) and the new BALL_DEAD_ZONE/BALL_EASE/BALL_MAX_PAN by w. A faster ball-mode pan is required: the long_pass clip moves the ball 460 px in 1 s, and MAX_PAN 0.1 cannot keep it in a 202-px crop. With no ball the plan is exactly the T-045 plan, so the existing 25.6 px step tests still hold.
- T-020 (R-004): Tuning is allowed only within: BALL_LEVEL [140, 200], BALL_FILL [0.3, 0.6], BALL_GATE [0.2, 0.4], BALL_LOST [3, 10], BLEND_STEP [0.1, 0.5], BALL_EDGE [0.05, 0.3], BALL_DEAD_ZONE [0.01, 0.06], BALL_EASE [0.3, 0.8], BALL_MAX_PAN [0.2, 0.6]. BALL_BOXES=(3,5), BALL_RING=2 and BALL_NMS=3.0 are fixed. The README records the final values. If no setting meets the gates, the Developer reports BLOCKED with the best JSON, and the Tech Lead decides.
- T-020 (R-004): The merge gate on the synthetic eval-crop set: aggregate ball_in_crop >= 0.95; occluded and white_distractor each >= 0.9; players_in_crop >= the T-045 camera measured in the same run (ball_candidates patched to []), with reference 0.5988; jitter <= 0.002, the T-045 'no jitter regression' bound; seconds_per_min <= 6.0. A 60 s 1280x720 field clip must plan in <= 6.0 s, reported in the PR.
