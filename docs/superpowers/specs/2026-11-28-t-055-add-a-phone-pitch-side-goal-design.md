# T-055: Add a phone/pitch-side goal eval set, a goal_coverage score, and make the eval use top=None like the pipeline

Request R-010. Request design: `docs/superpowers/specs/2026-11-28-r-010-t-i-test-upload-video-b-design.md`. Plan: `docs/superpowers/plans/2026-11-28-t-055-add-a-phone-pitch-side-goal.md`.

## Product Owner request

Tôi đã test upload video bóng đá của chúng tôi lên trong source, hiện tại phần cắt các đoạn highlight vẫn không chính xác nhất là phần bàn thắng. Kiểm tra và fix bug nếu có

## Goal

Measure first: add tests/fixtures/eval_phone/build.py, reusing the helpers in tests/fixtures/eval/build.py by import, plus labels.json for two 600 s cases (pitch_a, pitch_b) at 160x90 and 10 fps. Each case has no scoreboard, a high-contrast static fence/roofline in the top band that shifts a few pixels at 'camera pans' every 60-100 s, and two goals per case. A goal is a cheer of 7-8 s at +12 dB in 300-3000 Hz, followed by a kickoff whistle about 40 s later; the goal label is [t0-10, t0+6], so it includes the build-up. Each case also has 2-3 s shouts labelled 'chance' and one 8-10 s wind gust below 300 Hz at +12 dB as an unlabelled distractor. evaluate_dir gains a top-level `goal_coverage` (the share of goal labels fully inside a predicted 'goal' segment, null when there are no goal labels) and calls detect.find_highlights(video, top=None) so it scores the same candidates as pipeline.run. This changes the T-010/T-013 decision; the broadcast set must print the same f1/precision/recall/per_event as before, and the PR quotes both JSONs. Record the phone baseline JSON in the README under 'Kết quả đo video quay điện thoại (R-010)' and in DECISIONS.md; low goal precision and coverage are expected and not gated. The Tech Lead also runs `python -m sportscut cut sportscut-data/jobs/370c35dc-0461-476b-ace9-86b279f9479e/input /tmp/r010-before` on main and logs the goal-clip count, their reasons and the wall time. Assumption: the cue model is a stand-in until the PO adds labels in data/eval/; no real media is committed.

## Decisions

- T-055 (R-010): evaluate_dir calls `detect.find_highlights(video, top=None)` (video positional, top keyword, no other arguments), so the eval scores the same uncapped candidates as pipeline.run. This changes the T-010 'default options' decision and the T-013/T-014/T-015 chain wording; the rest of the chain is unchanged.
- T-055 (R-010): `goal_coverage` is a top-level eval key placed between precision_at_5 and per_match. It equals the pooled covered goal labels divided by all goal labels, rounded to 4 decimals, and is null when there are no goal labels. A goal label is covered when some segment with event 'goal' satisfies start <= label.start and label.end <= end (inclusive, no epsilon). Coverage is not one-to-one, and per_match entries and summarize() keep their exact keys.
- T-055 (R-010): tests/fixtures/eval/build.py stays untouched because ungated T-013/T-014/T-015 scope tests freeze it. The phone builder imports W, H, FPS, AUDIO_RATE, _band_noise and _ramp from it with importlib and keeps its own encode function, which copies the broadcast ffmpeg arguments.
- T-055 (R-010): The phone cue model has 2 cases x 600 s at 160x90 and 10 fps, no scoreboard, and a static sky/roofline/fence top band whose posts (period 8 px) shift +3 px at every pan (offset = 3*k mod 8, so no state repeats within 7 pans and no false 'revert'). Goal = cheer 7–8 s at +12 dB in 300–3000 Hz plus a 3 kHz kickoff whistle (1 s, amp 0.1) at t0+40. Goal label [t0-10, t0+6], chance shout 2–3 s with label [t0-4, t0+4], and one unlabelled gust of 8–10 s at +12 dB in 30–300 Hz. Seeds are 1501 and 1502, and the exact tables are in the spec.
- T-055 (R-010): Eval stubs that replace detect.find_highlights must accept `**kwargs` from now on. The eight signature edits and the two key-set unions (`| {'goal_coverage'}`) listed in the spec follow the intended change and do not weaken tests (same rule as the T-013/T-014/T-015 stub decisions). README contract tests and REPORT_KEYS stay unchanged because they check historic blocks.
- T-055 (R-010): The phone baseline JSON is recorded in README under '### Kết quả đo video quay điện thoại (R-010)', after 'Baseline đo trong T-055:', and in DECISIONS.md. It is not gated; low goal precision and coverage are expected. A later detection fix must not lower broadcast F1 and should raise phone goal_coverage.
- T-055 (R-010): The README addition uses a '###' heading inside the eval section, so '## ' heading lists and '\n## ' section splits used by older tests are unaffected.
- T-055 (R-010): The budget is < 600 changed lines outside docs/superpowers, generated labels.json included. Developer tests and Tester tests are each ≤ 170 lines. Scope and size are checked by review commands, not by new pytest git-diff tests (T-052 rule).
- T-055 (R-010): The Tech Lead logs the real-footage run of `sportscut cut sportscut-data/jobs/370c35dc-.../input /tmp/r010-before` on main (goal-clip count, reasons, wall time) in DECISIONS.md. It is a manual baseline, never a pytest test, and the 4 GB input is never committed.
